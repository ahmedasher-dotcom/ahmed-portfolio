About My Website

I created this personal portfolio website for Assignment 1. In this site you will find four primary pages:

- Home: An introudion page to my portfolio and work.
- About Me: A glimpse of my background, showing a profile photo and an introduction video of me.
- Projects: An overview of 6ix different projects I have completed in the past few months. 
- Contact Me: A form built with native HTML5 validation to contact me.

Technologies Used

- HTML5 
- CSS3
- Fluid, responsive design principles 


Responsive Design

In order to handle different types of devices, I ensured to avoid flexbox completly. Therefore I dedicated three seperate CSS stylesheets based on devices. 
- Desktop Layout: This layout applies to screens 1025px and wider via desktop.css.
- Table Layout: This layout applies to screens from 601 px to 1024px via tablet.css.
- Mobile Layout: This layout applies to screens 600px and smaller via mobile.css
For mobile devices and tablets, the layout automatically shifts in order for the content boxes to stack vertically, making it more accessbile to navigate. 

Color Scheme

For my portfolio I chose a clean, cohesive sytle, I used Adobe Color to put together a subtle palette of cream, brown and charcoal touch ups. The exact hex which I used accross all four pages include:
- Cream: #F8F5F0
- Charcoal: #262626
- Brown: #A77C59
- Sand: #E5D8C8
- White: #FFFFFF


CSS Gradients
I chose two specific types of linear gradients to add depth to the layout:
- Top Banner: A smooth, horizontal transition: linear-gradient(to right, #E5D8C8, #F8F5F0)
- Main Content Area: A subtle angled blend: linear-gradient(135deg, #FFFFFF, #E5D8C8)

Video Implementation

The About Me section includes a self-introduction video using the native HTML5 <video> tag. I included default browser playback controls and mapped a custom poster image to display before the video plays.

Contact Form

The Contact Me page uses the standard HTML5 validation attributes to check user inputs are valid before they submit. The form processes on a basic mailto: action, which means users will need to use there email to send the completed form.
